# iPhone 单次验收流程

这是测试清单，不是已通过报告。首次安装须先按 README 在 Mac 构建。没有提供 IPA，也没有发布至 TestFlight。

## 1. 不去操场，先验证本地模拟

1. 打开 App，保留默认“本地模拟测试”。此时不会加载学校网页或访问学校 API。
2. 点“中文语音试听”，确认实际听到声音。
3. 设置：每 10 秒更新一个点位；初始距离 800 米；运行上限 180 秒；关闭漏扫。
4. 点“开始监测”。首页应从 **800 米 / 2 圈**开始，不能从零圈开始。
5. 等待至少 30 秒：同一条记录被查询多次不增加圈数，也不反复播报。新点位更新后，每增加 200 米，圈数增加 0.5 圈，并播报一次变化。
6. 停止后应不再查询、不再继续播报，倒计时显示“—”，旧距离标为历史数据。重新开始应生成新的一轮报告。
7. 开启漏扫，再测一次。模拟平台会跳过一个点位；客户端不应凭查询次数、定位或预计时间确认那个点。短间隔用于 UI 验证；验证迟到提醒时建议将点位间隔改为 30 秒或以上，并留足预计间隔的 1.6 倍加 20 秒。
8. 点“保存当前测试 JSON”再“导出最近保存的 JSON”，通过系统分享保存到“文件”或私下发给维护者。

## 2. 学校登录与前台 API

1. 停止模拟，关闭“本地模拟测试”，选择早操或晚操。
2. 点“登录学校 → 进入健身长跑”，自行完成 WebVPN 和学校登录，不向他人发送密码或验证码。
3. 在学校首页点“健身长跑”，确认出现跑操距离、锻炼时长、跑操过程。
4. 点 App 导航栏右上角 **返回监测**。不要按退出 App，不要关闭整个程序。
5. 点“开始监测”。对照学校网页：距离、总用时、考勤类型是否一致。
6. 如果尚未起跑，没有点位变化时不反复播报是预期行为；API 可用与真实打卡链路通过是不同验收项。
7. 如会话未识别：返回学校首页并重新进入健身长跑后重试一次；仍失败则导出报告。不要反复提交密码，不要把 Cookie/Token 贴进反馈。

## 3. 后台和息屏专项（必须真机）

分开做两轮：第一轮不开定位；第二轮在真实运动时开启定位。模拟模式不会申请后台定位。

每轮依次做：前台 1 分钟 → 切换其他 App 1 分钟 → 返回检查 → 锁屏 1 分钟 → 返回 → 锁屏 5 分钟 → 返回 → 停止并导出。

人工记录每次离开/返回的时间、新打卡出现时间以及是否实际听到播报。报告中的 `speechQueued` 仅表示已调用 TTS，`speechStarted`/`speechFinished` 是系统回调，仍不能替代实际听感确认。没有 `speechStarted` 时重点检查系统是否暂停执行或音频启动失败。

`executionGap` 说明两次查询间隔超过 45 秒，不直接证明原因。`backgroundQueries` 不是锁屏次数。iOS 可能暂停后台任务，不能仅根据前台模拟通过宣称后台已适配。

## 4. 异常场景

- 查询时停止，然后马上重新开始：旧请求不能覆盖新一轮界面或播报。
- 临时断网：显示失败并停止，不能继续用旧数据声称打卡成功。
- 拒绝定位：仍能前台查询，不能阻止基础功能。
- 已有非零距离时重新进入：圈数仍以服务器距离除以 400。
- 换考勤：先停止，选择另一考勤，再开始；不复用旧记录作为新打卡。
- 临时来电或其他音频打断：返回后试听，导出带声音事件的报告；不要把没有听到误标为通过。
